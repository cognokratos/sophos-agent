# Story 1.2: First Chat Path (UI ↔ Agent Engine ↔ Ollama)

**As a** learner,
**I want** to send a message and get a model response,
**so that** I know the local LLM is wired correctly.

---

## Acceptance Criteria

1.  A minimal SvelteKit chat interface renders, allowing a user to send a message.
2.  The UI streams the response tokens from the backend as they are generated.
3.  If the default `mistral` model is not available, the UI displays a clear, actionable message guiding the user to run the warmup/setup script.
4.  All API errors are surfaced in the UI using the standard `ApiError` envelope, providing a user-friendly message.

---

## Dev Notes (Technical Implementation Details)

### Frontend (Chat UI)
-   **File Location**: Implement the main chat interface in `src/routes/+page.svelte`. [Source: `architecture/source-tree.md`]
-   **Styling**: Use Tailwind CSS for a minimal, clean chat layout. [Source: `architecture/tech-stack.md`]
-   **Streaming**: Use the browser's `EventSource` API to connect to the `/api/chat` endpoint and listen for `token` events to stream the response. The UI must handle the SSE connection lifecycle. [Source: `architecture/coding-standard.md`]
-   **Error Handling**:
    -   On API responses that are not `200 OK`, parse the `ApiError` from the response body and display the `error.message` to the user. [Source: `architecture/coding-standard.md`]
    -   Specifically handle the `MODEL_UNAVAILABLE` error code to provide the specific guidance required by AC #3. The `/readyz` check from Story 1.1 can be used as a reference.

### Backend (API & Agent)
-   **File Location**: The chat endpoint logic will be in `src/routes/api/chat/+server.ts`. The core agent orchestration will be in `src/lib/agent/`. [Source: `architecture/source-tree.md`]
-   **API Endpoint (`/api/chat`)**:
    -   Implement a `POST` handler that accepts a `ChatRequest` body. [Source: `architecture/3-runtime-integration-details.md`]
    -   It must return a `ReadableStream` for Server-Sent Events (SSE).
    -   The endpoint should orchestrate the call to the LangGraph.js engine.
-   **Agent Engine (`src/lib/agent/`)**:
    -   Create a simple LangGraph.js graph that takes the user's message, calls the Ollama model, and streams back the response.
    -   For this story, no tools are required. The graph should be a simple input -> model -> output flow.
-   **Error Handling**:
    -   If the Ollama service is unreachable or the `mistral` model is not found, the agent/endpoint must return a `503 Service Unavailable` with the `ApiError` code `MODEL_UNAVAILABLE`. [Source: `architecture/coding-standard.md`]
    -   All other internal errors should be mapped to the appropriate `ApiError` codes.

### Shared Types
-   Use the shared types from `src/lib/chat.ts` and `src/lib/error.ts` for consistency between the frontend and backend. [Source: `architecture/source-tree.md`]
