# Story 2.3: Trace & Markdown Integration

**As a** student,
**I want** to see and record tool calls,
**so that** I can understand how reasoning leads to external actions.

## Acceptance Criteria

1.  Tool invocations appear as steps in the trace.
2.  Markdown persistence captures the tool invocation blocks.

## Dev Notes

This story focuses on ensuring that when an agent uses a tool, the invocation and result are correctly recorded in both the real-time trace and the persistent markdown logs. This is critical for the "Inspect Everything" learning goal.

### Technical Context from Architecture Docs:

- **Previous Story Insights**: Story 2.2 demonstrated the use of Memory and Fetch MCPs. This story will ensure that the tool calls made in those examples (and any future tool calls) are properly traced and persisted.
- **Trace Persistence**: The `trace.jsonl` file, located in `/data/logs/{sessionId}/`, should be appended with `TraceNote` events. For tool calls, this should include events that detail the tool being called, the arguments, and the result. [Source: `docs/architecture/3-runtime-integration-details.md#3.6-markdown-persistence-layout`]
- **Trace Event Schema**: The `trace.jsonl` should contain JSON objects with `ts`, `node`, `event`, and `data` fields. For a tool call, we expect events like `tool_start` and `tool_end` or similar, with relevant data. [Source: `docs/architecture/coding-standard.md#logging--tracing`]
- **SSE Trace Events**: The `/api/chat` endpoint should stream `trace` events over SSE. These events should be of type `TraceNote`. This allows the UI to display the reasoning trace in real-time. [Source: `docs/architecture/coding-standard.md#streaming-protocol`]
- **Markdown Persistence**: In addition to the `trace.jsonl`, the assistant's response in the markdown file (e.g., `0002.assistant.md`) should include a representation of the tool call. This could be a formatted block showing the tool name, arguments, and a summary of the result.
- **Core Workflow**: The `LangGraph.js Engine` is responsible for invoking tools and logging events. The `toolNode` in the graph is the likely place to ensure these trace events are emitted. [Source: `docs/architecture/6-core-workflows.md#6.1-happy-path-chat-llm-tools-response`]
- **File Locations**: The core logic for this will likely reside in `src/lib/agent/` (specifically the graph nodes) and `src/lib/agent/persistence/` (for writing to the files).
