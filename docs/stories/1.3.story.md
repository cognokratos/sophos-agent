# Story 1.3: Reasoning Trace & Markdown Persistence

**As a** student,
**I want** to see orchestration steps and have chats saved,
**so that** I can study how agents reason and reproduce sessions.

---

## Acceptance Criteria

1.  A trace of the agent's reasoning is visible in the UI for each turn, updating in real-time.
2.  The full conversation is persisted to a unique markdown file after each message exchange.
3.  All data storage is confirmed to be local-only, with no external telemetry calls.

---

## Dev Notes (Technical Implementation Details)

### Previous Story Insights
The core UI-to-Agent chat loop (`src/routes/+page.svelte` ↔ `src/routes/api/chat/+server.ts`) is functional using Server-Sent Events (SSE). This story builds on that foundation by hooking into the agent's execution lifecycle to extract and persist its internal state.

### Backend (Agent & Persistence)
-   **File Location (Persistence)**: All new file writing logic should be implemented in `src/lib/agent/persistence/`. This module will be responsible for handling both markdown conversation logs and structured `trace.jsonl` files. [Source: `architecture/source-tree.md`]
-   **File Location (Agent)**: The LangGraph.js agent in `src/lib/agent/` must be modified to generate and emit trace events during its execution.
-   **Persistence Format**:
    -   Conversations will be stored in `data/logs/{sessionId}/`.
    -   Each turn will be a separate file (e.g., `0001.user.md`, `0002.assistant.md`).
    -   A `trace.jsonl` file will contain a stream of `TraceNote` objects. [Source: `architecture/3-runtime-integration-details.md`]
-   **Data Models**:
    -   The primary data structure is the `TraceNote` type from `src/lib/chat.ts`.
    -   The trace log (`trace.jsonl`) is a newline-delimited JSON file, where each line is a `TraceNote` object prefixed with a timestamp, e.g., `{"ts":"...", "node":"...", "event":"..."}`. [Source: `architecture/coding-standard.md`]
-   **API Modifications**:
    -   The existing `GET /api/chat` SSE stream must be enhanced. In addition to `token` events, it must now emit `trace` events, with the event data being a `TraceNote` object. [Source: `architecture/3-runtime-integration-details.md`]

### Frontend (Trace UI)
-   **File Location**: The main chat interface in `src/routes/+page.svelte` will be modified.
-   **Real-time Trace View**:
    -   The client-side `EventSource` logic must be updated to handle the new `trace` event type.
    -   A new UI component should be created to render the sequence of `TraceNote` events as they are received. This provides the live reasoning view required by AC #1.
-   **Error Handling**: No changes are expected for error handling in this story, but existing `ApiError` standards must be maintained.

### Testing Requirements
-   Add unit tests for the new persistence writer functions in `src/lib/agent/persistence/` to ensure correct file and directory creation and proper formatting.
-   Update Playwright E2E tests to verify that for a given chat interaction:
    1.  `trace` events are received by the client.
    2.  The reasoning trace is displayed in the UI.
    3.  Markdown files (`.md`) and a `trace.jsonl` file are created in the `data/logs/{sessionId}` directory.
-   [Source: `architecture/coding-standard.md`]
