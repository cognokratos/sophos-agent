# Story 3.1: Load Conversation History

**Status:** Draft

---

## Story

**As a** user,
**I want** the chat application to automatically load my previous conversation when I open it,
**so that** I can immediately resume where I left off without interruption.

---

## Acceptance Criteria

1.  When the application starts, the messages from the most recently accessed conversation are loaded and displayed in the chat window.
2.  The loaded messages appear in the correct order (chronological).
3.  If no previous conversations exist, the application starts with a clean, empty chat interface.
4.  The loading process is visually indicated to the user (e.g., a loading spinner) if it takes more than a brief moment.

---

## Tasks / Subtasks

-   [ ] **Backend:** Identify and retrieve the most recent conversation file.
-   [ ] **Backend:** Create an endpoint to serve the content of a specified conversation file.
-   [ ] **Frontend:** On application load, call the backend to get the latest conversation.
-   [ ] **Frontend:** Parse the markdown file content into a structured message format.
-   [ ] **Frontend:** Render the array of messages in the chat UI.
-   [ ] **Frontend:** Implement a loading state in the UI while messages are being fetched.

---

## Dev Notes

-   Refer to `docs/architecture/source-tree.md` for file structure and where conversation files are stored.
-   The persistence mechanism is markdown-based. The parsing logic must be robust.
-   The API endpoint should be designed to fetch a conversation by a unique identifier (e.g., filename).

### Testing

-   Unit tests should cover the markdown parsing logic.
-   Integration tests should verify the frontend correctly fetches and displays data from the backend.
-   E2E tests should simulate a user opening the app and seeing their last conversation.
