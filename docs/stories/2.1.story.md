# Story 2.1: Integrate LangChain MCP Adapters

**As a** developer,
**I want** to integrate the `@langchain/mcp-adapters` library,
**so that** the agent can connect to and utilize external MCP tools.

## Acceptance Criteria

1.  The `@langchain/mcp-adapters` library is installed and configured.
2.  A `MultiServerMCPClient` instance is initialized at agent startup, connecting to specified MCP servers.
3.  The agent can retrieve and utilize tools exposed by the `MultiServerMCPClient`.
4.  Unit tests confirm successful client initialization and tool retrieval.

## Dev Notes

This story focuses on integrating the `@langchain/mcp-adapters` library to enable the Sophos Agent to consume external MCP tools. The primary component to integrate is the `MultiServerMCPClient`.

### Technical Context from Architecture Docs:

- **MCP Tool Consumption**: Instead of defining our own `McpTool` interface, we will leverage the tool format provided by `@langchain/mcp-adapters` when retrieved via the `MultiServerMCPClient`.
  - **Source**: `docs/architecture/coding-standard.md#mcp-tool-adapters` (will need to be updated to reflect this change)

- **File Location**: The `MultiServerMCPClient` initialization and tool retrieval logic should be integrated into the agent's core, likely within `src/lib/agent/index.ts` or a new dedicated module within `src/lib/agent/mcp/`.
  - **Source**: `docs/architecture/source-tree.md`

- **Type Safety**: All new code must be strictly typed using TypeScript. The use of `any` is forbidden.
  - **Source**: `docs/architecture/coding-standard.md#language--type-system`

- **Configuration**: MCP server connection details (e.g., `stdio` commands, `sse` URLs) should be configurable, potentially via environment variables or a dedicated configuration file.

- **Testing**: Unit tests are required for the new functionality, especially for client initialization and tool retrieval. A new test file `src/lib/agent/mcp/mcp-client.spec.ts` should be created. The project uses Vitest.
  - **Source**: `docs/architecture/coding-standard.md#testing-requirements`

## Tasks / Subtasks

1.  **(AC: 1)** **Install `@langchain/mcp-adapters`**:
    - [x] Add `@langchain/mcp-adapters` to `package.json` and install it.

2.  **(AC: 2)** **Configure MCP Servers**:
    - [x] Define a mechanism for configuring MCP server connections (e.g., `MCP_SERVERS` environment variable, or a new config file). This should include transport type (`stdio` or `sse`), command/args for `stdio`, and URL for `sse`.

3.  **(AC: 2)** **Initialize `MultiServerMCPClient`**:
    - [x] Create a new module, e.g., `src/lib/agent/mcp/client.ts`, to encapsulate the `MultiServerMCPClient` initialization.
    - [x] Initialize the `MultiServerMCPClient` at agent startup using the configured MCP server details.

4.  **(AC: 3)** **Retrieve and Expose Tools**:
    - [x] Modify the agent's core (e.g., `src/lib/agent/index.ts`) to retrieve tools from the initialized `MultiServerMCPClient`.
    - [x] Expose these tools in a way that the agent can utilize them (e.g., add them to an internal tool list or registry).

5.  **(AC: 4)** **Implement Unit Tests**:
    - [x] Create `src/lib/agent/mcp/mcp-client.spec.ts`.
    - [x] Write unit tests for the `MultiServerMCPClient` integration.
    - [x] Include tests for:
      - Successful initialization of the client with mock server configurations.
      - Successful retrieval of tools from mock servers.
      - Error handling for invalid server configurations or connection issues.
    - [x] Reference `docs/architecture/coding-standard.md#testing-requirements`.
