# Story 3.2: Create a New Conversation

**Status:** Done

---

## Story

**As a** user,
**I want** to be able to start a new conversation at any time,
**so that** I can discuss a new topic without mixing it with my previous chat history.

---

## Acceptance Criteria

1.  A "New Chat" or similar button is clearly visible in the user interface.
2.  Clicking the "New Chat" button archives the current conversation and presents a new, empty chat window.
3.  The new conversation is assigned a unique identifier and a new markdown file is created for it once the first message is sent.
4.  The application state correctly reflects that the user is in a new, unsaved conversation.

---

## Tasks / Subtasks

- [x] **Frontend:** Add a "New Chat" button to the UI layout.
- [x] **Frontend:** Implement client-side logic to clear the current chat view and reset the conversation state when the button is clicked.
- [x] **Backend:** Create an endpoint or mechanism to generate a new unique conversation ID.
- [x] **Backend:** Ensure that the persistence logic creates a new file for the new conversation upon receiving the first message.
- [x] **Frontend:** Wire the UI to the backend logic for creating a new conversation.

## Dev Notes

- The "New Chat" action should feel instantaneous to the user.
- Consider how to handle the transition from an existing conversation to a new one. Does the old one get saved automatically? (Yes, based on current persistence logic).
- The new conversation should only be persisted once the first message is exchanged to avoid creating empty files.

### Testing

- Unit tests for the UI component handling the "New Chat" action.
- Integration test to ensure a new file is created on the backend after starting a new chat and sending a message.
- E2E test to simulate a user completing one conversation, starting a new one, and verifying both are saved correctly.
