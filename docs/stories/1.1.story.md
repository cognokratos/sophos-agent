# Story 1.1: Docker Compose Baseline & Healthchecks

**As a** new user,
**I want** to start everything with one command,
**so that** I can run the system without manual wiring.

---

## Acceptance Criteria

1.  `docker-compose.yml` defines all services (`web`, `ollama`, `mcp-memory`, `mcp-fetch`) with pinned versions and healthchecks.
2.  The main `README.md` includes a "Quickstart" section with a copy-paste runnable `docker compose up` command.
3.  Logs from `docker compose up` show all services reaching a healthy state.
4.  The `web` service's `/healthz` and `/readyz` endpoints return `200 OK`.

---

## Dev Notes (Technical Implementation Details)

### Docker Compose Configuration
-   **File Location**: Create the primary Docker Compose file at `infra/docker-compose.yml`. [Source: `architecture/source-tree.md`]
-   **Services**:
    -   `web`: Build from `infra/Dockerfile.web`. Expose port `5173`.
    -   `ollama`: Use the official `ollama/ollama` image with a pinned version. [Source: `architecture/tech-stack.md`]
    -   `mcp-memory`: Use the official `mcp/memory` image with a pinned version.
    -   `mcp-fetch`: Use the official `mcp/fetch` image with a pinned version.
-   **Healthchecks**:
    -   All services must have a healthcheck.
    -   The `web` service healthcheck should target the `/healthz` endpoint. [Source: `architecture/4-deployment-topology-docker-compose.md`]
-   **Versioning**: Pin all image tags in the `docker-compose.yml` file to prevent version drift. [Source: `architecture/tech-stack.md`]
-   **Environment**: Use the environment variables defined in `.env.example`. [Source: `architecture/source-tree.md`]

### Health & Readiness Endpoints
-   **File Location**: Implement endpoints in `apps/web/src/routes/api/`. [Source: `architecture/source-tree.md`]
-   **`/healthz`**: A simple liveness check that returns `200 OK` to indicate the server is running.
-   **`/readyz`**: A readiness check that confirms connectivity to `ollama` and that the default model (`mistral`) is available. [Source: `architecture/4-deployment-topology-docker-compose.md`, `architecture/tech-stack.md`]

### Documentation
-   Update `README.md` with a "Quickstart" section. It must contain the exact command to bring the system up (e.g., `docker compose up --build`).
